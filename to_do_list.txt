Build a real, production-ready online education platform for Data Analytics using Django.

This must NOT be a prototype with fake functionality.

Actually create the project, implement the features, run the application, run tests, identify errors, fix them, and verify the important user flows.

---

# 1. PROJECT GOAL

Create an online learning platform where students can learn Data Analytics through Uzbek-language lectures, complete interactive exercises, submit homework, track their progress, and where teachers/admins can monitor student performance.

The first active section must be:

Other Data Analytics sections must already exist in the architecture/database but remain hidden from students until published.

* Excel
* Power BI
* Statistics

* Real Projects

* Gamification

# 10. SQL ANSWER VALIDATION

DO NOT compare SQL strings.

Different valid SQL queries can produce the same correct result.

Example:

```sql
SELECT customer_id, COUNT(*)
FROM transactions
GROUP BY customer_id;
```

and:

```sql
SELECT customer_id, COUNT(transaction_id)
FROM transactions
GROUP BY customer_id;
```

Both can be correct.

Therefore compare the resulting datasets.

Validation should consider:

* Row order
* Column order where appropriate
* NULL values
* Empty results
* Numeric precision
* Data types where appropriate

Implement a reliable result comparison service.

---

# 11. SQL SANDBOX SECURITY

CRITICAL:

NEVER execute student SQL against the production database.

Architecture:

```text
Student
   ↓
Django
   ↓
SQL Sandbox
   ↓
Sandbox PostgreSQL
   ↓
Result
   ↓
Django
   ↓
Student
```

The sandbox must use:

* Separate PostgreSQL database
* Separate restricted database user
* Educational datasets only
* No production database access
* Query timeout
* No server filesystem access
* No destructive SQL
* Restricted PostgreSQL functionality
* Read-only permissions where possible

Prevent:

* DROP
* DELETE
* UPDATE
* INSERT
* ALTER
* CREATE
* TRUNCATE
* COPY
* Dangerous extensions/functions
* Access to filesystem
* Access to production database

Do not rely only on frontend validation.

All SQL security checks must happen server-side.

Design the system so the SQL execution layer can later be moved to isolated Docker containers.
